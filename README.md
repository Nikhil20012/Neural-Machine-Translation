# Neural Machine Translation: English to Hindi

A comparative study of two encoder-decoder architectures for English-to-Hindi translation, trained on the IIT Bombay parallel corpus. This project implements and evaluates a vanilla LSTM model against a GRU-based model with dot-product attention to understand how attention mechanisms affect translation quality, particularly on longer sentences.

## Key Findings

The attention-based model consistently outperforms the LSTM model on sentences longer than a few words. Without attention, the encoder must compress the entire source sentence into a single fixed-size vector, which loses information as sentence length grows. The attention mechanism lets the decoder selectively reference different parts of the source at each decoding step, producing more accurate translations for complex inputs.

Both models handle short, formulaic phrases well (single words like "method" or "value" translate perfectly), but the LSTM model's output degrades noticeably on longer inputs while the attention model remains coherent.

Detailed analysis and methodology are documented in `docs/NMT_Research_Paper.pdf`.

## Models

**LSTM Encoder-Decoder (no attention)**
- Embedding dim: 256, single LSTM layer for both encoder and decoder
- Encoder compresses source into final (h, c) states; decoder generates from that fixed context
- Trained 70 epochs with RMSprop on TPU
- Training accuracy reaches ~90%, but validation loss diverges after epoch 12 (overfitting)
- ~7.9M parameters

**GRU Encoder-Decoder with Dot-Product Attention**
- Embedding dim: 64, hidden units: 1024, single GRU layer for both encoder and decoder
- At each decoder step, computes attention over all encoder hidden states
- Trained 100 epochs with Adam (lr=0.006) on GPU
- Custom training loop with teacher forcing and masked loss
- Training loss drops from ~23 to ~1

## Dataset

[IIT Bombay English-Hindi Parallel Corpus](https://www.cfilt.iitb.ac.in/iitb_parallel)

The full corpus contains ~1M sentence pairs. Both models use a filtered subset of 25,000 pairs with sentence length caps (10 words for LSTM, 16 words for attention) to keep training feasible. Vocabulary is capped at 10,000 words for both languages.

## How to Run

Both notebooks are designed for Google Colab.

**LSTM model** (`Neural Machine Translation using LSTM.ipynb`)
- Requires TPU runtime for reasonable training speed
- Requires TensorFlow 2.6.0 and Keras 2.6
- Update all file paths (dataset root, model checkpoint, preprocessed data pickle) to match your Google Drive layout
- Download the IITB parallel corpus files (`IITB.en-hi.en` and `IITB.en-hi.hi`) and place them in your Drive

**Attention model** (`S2S-Attention.ipynb`)
- Requires GPU runtime
- Update the dataset path to point to `dataset_tdl.csv` (the merged dataset generated by the notebook)
- Run cells sequentially; the notebook handles dataset creation, training, and inference

## Future Work

This project was completed in 2022 as a comparative study of RNN-based translation
architectures. The NMT landscape has changed dramatically since then, with Transformer
models (and their descendants) becoming the standard for production translation. Both
models here would be outperformed by even a small Transformer trained on the same data,
and massively outperformed by pretrained multilingual models like IndicTrans2 or NLLB,
which now cover English-Hindi with strong quality out of the box.

The most interesting evolution of this work would be using translation not as the end
product but as a component inside a larger system. Recent research on multilingual RAG
(CrossRAG, QTT-RAG, IndicRAG) shows that translation models are now embedded within
retrieval-augmented generation pipelines, where they bridge the gap between a user's
query language and an English-dominant knowledge base. This is exactly the problem
motivating this project: Hindi-speaking users who need access to information that exists
primarily in English.

**Cross-lingual RAG for Indian government schemes**: millions of Indians are eligible for
welfare schemes (PM-KISAN, Ayushman Bharat, MGNREGA) but the eligibility rules,
application procedures, and FAQs exist mostly in English PDFs and legal documents. A
cross-lingual RAG system would let a Hindi-speaking user ask a question in Hindi and get
an accurate, grounded answer by: (1) translating the query to English, (2) retrieving
relevant chunks from an English knowledge base using multilingual embeddings, (3)
generating the answer grounded in the retrieved context, and (4) translating the response
back to Hindi. The NMT models from this project serve as the conceptual starting point
for steps 1 and 4, with IndicTrans2 or NLLB as the upgraded translation layer. The key
research challenge is translation quality scoring: recent work like QTT-RAG (2025) shows
that poor translations in the pipeline cause hallucinated answers, so a quality-aware
tagging system that flags low-confidence translations before they enter the generation
step would be critical for trustworthiness. A prototype stack: FastAPI backend, Qdrant or
FAISS for vector storage, multilingual embeddings (textembedding-gecko or IndicBERT) for
cross-lingual retrieval, IndicTrans2 for translation, and an LLM (Claude API or fine-
tuned mT5) for grounded generation, with a Streamlit frontend where users type questions
in Hindi and get cited answers pulled from official government PDFs.

If building on the model comparison work directly:

- **Replace RNNs with a small Transformer**: even a 2-layer, 4-head Transformer encoder-
  decoder trained on the same 25K pairs would likely beat both models and demonstrate
  the architectural advantage more clearly. This would complete the comparison across
  three generations of seq2seq: vanilla RNN, RNN + attention, and Transformer.

- **Scale to the full corpus**: the 1M-pair IITB corpus was never fully used due to Colab
  constraints. Training on even 200K pairs with gradient accumulation would show how
  each architecture scales with data, which is arguably more interesting than the
  architecture comparison alone.

- **Add BLEU and chrF evaluation**: the current project evaluates qualitatively (eyeballing
  translations). Adding automated metrics like BLEU, chrF, and TER would make the
  comparison rigorous and publishable. The candidate/reference lists are already set up
  in the attention notebook but never scored.

- **Use subword tokenization**: both models use word-level tokenization, which handles
  Hindi's rich morphology poorly. Switching to SentencePiece or BPE would reduce the
  out-of-vocabulary problem and likely improve both models, especially on rare word
  forms.

Other production-oriented directions:

- **Domain-specific translation API for government documents**: India has a real need for
  translating government records, legal notices, and public health advisories from
  English to Hindi. A fine-tuned IndicTrans2 model served behind a FastAPI endpoint,
  with a simple web UI for clerks to paste text and get translations, would be
  immediately useful. The IITB corpus could be supplemented with domain-specific
  parallel data scraped from government bilingual websites.

- **Real-time subtitle generation for Hindi educational content**: pair a translation
  model with Whisper (speech-to-text) to auto-generate Hindi subtitles for English
  lecture videos. Universities and MOOCs targeting Hindi-speaking students could
  integrate this as a pipeline: audio in, English transcript, Hindi translation,
  SRT file out.

- **Translation quality estimation layer**: instead of just translating, build a
  confidence scoring system that flags low-quality translations for human review.
  This is what production translation systems actually need, since blindly trusting
  model output is risky for official documents. Could be implemented as a secondary
  model that scores each translation on fluency and adequacy.
